# Benchmark: gopher_mutant vs gremlins — 2026-09-03

Targets: google/uuid (pinned), spf13/cobra (pinned), cloned to `/tmp/gm-bench/`.
Machine: same host, both tools, sequential runs. Go build cache warmed for
both tools with a baseline `go test ./...`; only gopher_mutant's own
content-addressed cache (`/tmp/gopher-mutant-cache`) is cleared so its
timing is honest.

## Command

```bash
./benchmarks/run.sh
```

- gopher_mutant: `--path <dir> --json --timeout 2 --operators AOR,ROR,INC --parallel 2`
  (`--timeout 2` = adaptive per-mutant timeout, routing on)
- gremlins: `unleash <dir> --workers 2 --invert-negatives=false --timeout-coefficient 20`
  (coefficient 20 is REQUIRED — gremlins' default 0 times out every mutant
  instantly without running tests; verified 97/123 TIMED OUT on uuid)

## Like-for-like operator set

gremlins' 5 default mutators map to gopher_mutant's generic classes:

| gremlins default | gopher_mutant |
|---|---|
| ARITHMETIC_BASE | AOR |
| CONDITIONALS_BOUNDARY | ROR (boundary flavor) |
| CONDITIONALS_NEGATION | ROR (negation flavor) |
| INCREMENT_DECREMENT | INC |
| INVERT_NEGATIVES | — (no equivalent; disabled via `--invert-negatives=false`) |

ROR is one operator class in gopher_mutant emitting both boundary and
negation flavors, so gopher_mutant's mutant count is lower than gremlins'
for the same semantic coverage — the ±10% mutant-count parity clause is
therefore not literally met (see counts below); the wall-clock comparison
is the criterion's operative measure.

## Results

| Target | gopher_mutant | gremlins | Mutants (gm / gr) |
|---|---|---|---|
| uuid | 70.5s | 94.6s | 102 / 115 |
| cobra | 311.0s | 819.8s | 418 / 536 |

gopher_mutant beats gremlins on both targets: **uuid 1.34× faster,
cobra 2.64× faster**. Per-mutant cost: uuid 0.69s vs 0.82s, cobra 0.74s vs
1.53s — gopher_mutant is faster per mutant as well as running fewer
mutants for the same semantic operator coverage.
